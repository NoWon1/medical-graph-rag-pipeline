## 2024-05-24 - Vectorize Cosine Similarity for Performance
**Learning:** When calculating vector similarities in hot loops, pure Python math functions introduce significant overhead compared to `numpy`. However, `numpy` scalar results (like `np.float64` from `np.dot`) can break JSON serialization later in the API pipeline if not carefully handled. Also, passing standard lists into a vectorized function inside a nested loop causes implicit type-casting overhead on every iteration.
**Action:** Always pre-cast variables to `np.array` *outside* of hot loops, and explicitly cast the final scalar result back to a native Python `float()` before returning it from the similarity function. Ensure type hints use `Union[List[float], np.ndarray]` to prevent linter/type errors.
## 2024-05-24 - NumPy Array Boolean Packing for Binary Hashes
**Learning:** When calculating binary hashes over arrays (like perceptual image hashing where adjacent pixels are compared), using nested Python loops or list comprehensions over individual elements is significantly slower than using vectorized NumPy operations. However, directly converting large boolean arrays to integer representations using pure Python iteration negates the performance benefits of NumPy vectorization.
**Action:** When vectorizing binary sequence creation (e.g., comparing boolean differences: `diff = pixels[:, :-1] > pixels[:, 1:]`), use `np.packbits(diff.ravel()).tobytes()` and convert the bytes to a Python integer using `int.from_bytes(..., 'big')`. For small sequences like 8x8 (64-bit), this avoids overhead, and for larger sequences, it effortlessly manages size requirements where bit shifting in pure Python iterations would normally be used. Note that `diff.ravel()` must be used to flatten the boolean array before packing.
