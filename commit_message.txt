🧪 [testing improvement] Add error path test for process_single_pdf

🎯 **What:** The testing gap addressed
Added a missing error path test for `process_single_pdf` in `cancer_ingestion.py`. The original implementation handles exceptions gracefully using a `try-except` block but lacked testing for these edge cases due to the complex nature of mocking `fitz.open`.

📊 **Coverage:** What scenarios are now tested
The new test case `test_process_single_pdf_error_path` tests the error handling path when PyMuPDF (`fitz`) fails to open a provided PDF document. The test leverages `unittest.mock.patch` to simulate an exception inside `fitz.open`, as well as to mock filesystem operations (`Path.stat`) and unrelated expensive functions (`detect_cancer_type`) to keep the test fast and deterministic.

✨ **Result:** The improvement in test coverage
The error branch of `process_single_pdf` is now fully covered, verifying that the function correctly intercepts the exception and returns the expected failure dictionary (`{"file": name, "status": "failed", "error": str(e)}`) rather than crashing or swallowing the error silently.
